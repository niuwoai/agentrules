# 需求收集、验收与经验反馈

- 发布单元：Willdeep 规则库。
- 类型：Added / Changed；开发变更片段，未分配新版本，不代表已发布。
- 目标：补齐需求来源、澄清、范围、优先级、状态、验收证据与经验反馈，沿用已有 Issue / 任务系统和授权。

## Added

- 新增可按需加载的 `requirements.md`、需求记录模板和需求到经验的填写示例。
- 明确验收条件与任务、候选提交和实际验证证据的对应关系；范围变化后重评受影响证据。

## Changed

- 交付画像包含需求主题，独立选择主题及别名去重继续可用；默认必选主题不增加。
- 索引、项目 AGENTS、编程和设计入口说明需求主题读取时机。
- 经验记录明确触发条件、生成或更新步骤、位置继承、归并、验证和规则晋升，区分自动检查与人工审阅的实际执行证据；不强制新建单个 `LESSONS.md`，不新增自动生成工具。
- 同步可选模板、生成产物和产品 / 架构参考；正式版本与 CHANGELOG 在后续发布准备阶段统一归并。

## 验证范围

- 画像叠加、需求主题别名去重、full / compact / index 边界与入口读取指令。
- 现有需求与经验记录保留、AGENTS 脚手架仅写缺失规则、dry-run 不写入。
- 规则与生成产物同步、入口预算、版本一致性及既有发布脚本回归。

## 本地验证结果

- Ruby 3.2.4 与系统 Ruby 2.6.10 分别执行 `scripts/verify_rules.rb`，修正后均为 20 / 20 PASS，输出 JSON + Markdown 报告。
- 两套完整校验内的发布工作流隔离回归均为 7 runs、40 assertions、0 failures、0 errors、0 skips；未访问真实发布目标。
- 新入口反例：基线生成器的 generic / index / AGENTS 使用说明缺少需求读取指令，当前源通过。
- 内存快照反例：模拟首次生成后已有 `LESSONS.md` 的 CRLF 被改为 LF，原判定漏检，新增首次生成字节比较能够拒绝；未改写真实项目记录。
- 全量 compact 为 275 行 / 13,797 字符，低于 300 行 / 20,000 字符预算。

以上为当前工作区的本地验证，不代表远端 CI、已合入或已发布。
